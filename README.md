# DayZ RVMAT Studio

Графический редактор и генератор материалов `.rvmat` для DayZ. ТЗ: [docs/TZ.md](docs/TZ.md).

## Запуск

**Готовая сборка (Windows):** GitHub Actions → workflow `build` → артефакт `DayZRvmatStudio-win64.zip`
(распаковать, запустить `DayZRvmatStudio.exe`).

**Из исходников:**
```bash
pip install -r requirements.txt
python run_studio.py
```
**Собрать exe самому (Windows):** запустить `build_windows.bat` (создаёт venv, гонит тесты, собирает, делает `--selftest`).

CLI без GUI: `python -m rvmat_studio kit base.rvmat myhelmet out/` · `python -m rvmat_studio validate file.rvmat`

## Что умеет
- **Backend:** lossless-парсер RVMAT (неизвестные параметры/классы/комментарии сохраняются, числа как есть), модель материала, процедурные текстуры `color()`/`fresnel()`, `.bak` при перезаписи.
- **Комплекты:** base / damage / destruct / decorative / decorative_damage / decorative_destruct из одного материала; общие настройки распространяются на всех, переопределения — по состоянию или для всей decorative-ветки; различия показываются.
- **Редактор:** ползунок + точное поле + диапазон + сброс (↺) для чисел; RGBA + палитра для цветов; Stage1–7 с текстурой, миниатюрой, uvSource, aside/up/dir/pos, tiling/offset/rotation, Filter, процедурными параметрами; отключение стадии в превью не трогает RVMAT.
- **Предпросмотр:** OpenGL 3.3 (шейдер на GPU, MSAA 4×, мипмапы + анизотропия; автоматический откат на программный CPU-рендер, если GL недоступен или отключён в настройках) — модели (сфера, куб, цилиндр, плоскость, тор, тестовая модель, свои модели **OBJ и FBX**), вращение/зум/сдвиг, 5 схем освещения, своя панорама, режимы (AS, нормали, SMDI-каналы, detail, UV-шашечки), UV-развёртка, сетка, повторение текстуры, сравнение двух состояний.
- **Текстуры:** PNG/TGA/JPG/TIFF/BMP и чтение PAA (DXT1/3/5, ARGB, AI88, LZO); просмотр каналов, альфа, проверка нормалей, сравнение; автосопоставление по `_nohq/_as/_smdi` (стадии RVMAT) и `_co/_ca` (Base Color для превью); кэш миниатюр.
- **Пресеты:** 12 встроенных по категориям ТЗ, свои, копия, поиск, избранное, импорт/экспорт.
- **Проект:** undo/redo, история, автосохранение + восстановление, импорт готовых RVMAT (в т.ч. комплекта), пакетное редактирование файлов, копирование стадий, поиск, горячие клавиши, сохранение раскладки.
- **Диагностика:** критические/предупреждения/инфо, двойной клик — переход к параметру. Пути: P:/корень проекта, регистр, расширения, абсолютные пути Windows.
- **Экспорт:** один материал / комплект / проект (RVMAT + текстуры + `.rvproj`), проверка перед экспортом, защита от перезаписи.

Горячие клавиши: Ctrl+N/O/S/Shift+S, Ctrl+I импорт RVMAT, Ctrl+E экспорт комплекта, Ctrl+Z/Y, F2 переименовать, F5 диагностика, Ctrl+F поиск текстур.

## Быстрая настройка материала
Вкладка «Материал» открывается с ползунками по смыслу (0–100 %), а RGBA-поля свёрнуты в блок «Подробно». Каждый ползунок пишет **реальные поля RVMAT** и считывается из них обратно (правка «Подробно» двигает ползунки, ↺ возвращает исходные значения, одна правка = один шаг отмены), под ползунком показано, какое поле меняется:
- **Шероховатость** → `specularPower` (0 % = 200, резкий блик; 100 % = 1, матовый; шкала логарифмическая).
- **Сила блика** → `specular` (яркость, оттенок сохраняется).
- **Металличность** → макрос: поднимает `specular` до 0,1…1,0 и приглушает `diffuse`/`ambient` до 0,9…0,18. Это моя договорённость о том, как «металл» выглядит в RVMAT, а не параметр формата: настоящая металличность по пикселям задаётся текстурой SMDI.
- **Свечение** → `emmisive`.
- **Сила нормали** — **только предпросмотр** (в RVMAT такого поля нет, рельеф задаёт `_nohq`); хранится в проекте у каждого материала, в `.rvmat` не попадает.

## Части модели (селекшены) и несколько материалов
Вкладка «Части»: в проекте может быть несколько **материалов** (каждый — свой комплект из 6 RVMAT со своим именем, например `helmet`, `helmet_glass`), а каждой **части** модели назначается нужный. Предпросмотр рисует каждую часть своим материалом; клик по модели выбирает часть (подсветка + её материал становится редактируемым). Части без назначения используют первый материал.
- Части берутся из: групп `g`/`o` (или `usemtl`) в **OBJ**, отдельных объектов (Geometry) в **FBX**, зон встроенных моделей (сфера, куб, цилиндр, тестовая).
- Экспорт записывает комплекты всех материалов и файл `<проект>_selections.txt` (`селекшен;материал.rvmat`) — для переноса в Object Builder. Сами P3D-селекшены программа не читает и не пишет: имена частей FBX/OBJ — это имена объектов/групп, а не обязательно именованные селекшены P3D (в FBX они обычно не сохраняются).

## Workbench
«Инструменты → Проверить в Workbench» запускает `workbenchApp.exe -project=<dayz.gproj>` с рабочей папкой Workbench. Файл `dayz.gproj` ищется: указанный в Настройках → корень проекта/P: (и их папки `Workbench`) → DayZ Tools. Если не найден или P: не смонтирован — выводится понятное сообщение. Материал в Workbench нужно открыть вручную в Resource Browser (путь показывается). Флаг `-project` взят из руководств сообщества, **на реальных DayZ Tools не проверялся**.

## Нормали `_nohq`
В игровом PAA `_nohq` — DXT5 с перестановкой каналов (X нормали инвертирован и лежит в альфе). Декодер применяет обратную перестановку (по имени `_nohq` или тегу `SWIZ`), поэтому нормаль выглядит сине-фиолетовой, а не голубой. Источник описания — сторонний (пакет woozymasta/paa и конфиг TexView), **не официальная спецификация и не проверено на реальных PAA игры**. Исходные PNG/TGA не преобразуются.

## Честные ограничения
- Предпросмотр — **приближение** шейдера Super, не движок Enfusion (Справка → «Отличия предпросмотра от игры»). Трактовка каналов SMDI (R spec, G metal, B gloss, A glow) — оценочная.
- Stage3 для обычного (base) материала **не подтверждён образцами** (их не было); взят как у decorative, помечен `I300`.
- PAA: чтение mip 0 проверено на синтетических данных и рукописных LZO-потоках, **не на реальных игровых PAA**. Запись PAA — только через `ImageToPAA` из DayZ Tools; интеграция с DayZ Tools/Workbench реализована, но не проверена (требует Windows + установленные Tools).
- Модели: OBJ и FBX (бинарный 7.x и ASCII; без анимации, материалов и трансформаций узлов). P3D напрямую не читается — экспортируйте в FBX/OBJ. UV переворачивается по V, как в DCC-вьюпорте.
- Скорость предпросмотра (измерено на программном Mesa llvmpipe, без GPU): OpenGL ~7–17 мс/кадр (на реальной видеокарте быстрее), CPU-откат ~65 мс при правке параметров. GL и CPU дают близкую картинку (среднее расхождение <1/255 на тестовой сцене; в тестах допуск 6–8). **Не проверено на реальных Windows-драйверах** (Intel/AMD/NVIDIA).
- Рендер выбирается в Настройках (Авто / OpenGL / CPU) или переменной `RVMAT_RENDERER=cpu|gl`; применяется после перезапуска.
- Значения встроенных пресетов — стартовые ориентиры, не официальные значения BI.
- **Base Color (_co)** не хранится в RVMAT (в DayZ он приходит с текстуры грани модели), поэтому в программе это отдельная настройка *только предпросмотра* (вкладка «Общие» или ПКМ по текстуре → «Назначить как Base Color»); в `.rvmat` он не пишется. `_as` — **Ambient Shadow**: в превью затеняет только рассеянный свет и отражения, цвет не меняет. Какой именно канал `_as` несёт затенение, я принял за **R** — это допущение, поправьте, если в игре иначе.
- Интерпретация `uvTransform` (u' = aside·uv + pos) используется в превью и в «удобных» полях tiling/offset/rotation; сами aside/up/dir/pos всегда редактируются напрямую.

## Тесты
```bash
pip install -r requirements.txt pytest
QT_QPA_PLATFORM=offscreen pytest                       # CPU-путь, GL-тесты пропускаются
# с OpenGL (Linux): Xvfb + Mesa
LIBGL_ALWAYS_SOFTWARE=1 QT_QPA_PLATFORM=xcb xvfb-run -a pytest
```
