# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
# DayZ RVMAT Studio — визуальный редактор и генератор материалов

## 1. Цель проекта

Разработать полноценное настольное приложение для Windows 10/11, предназначенное для создания, редактирования, визуализации и экспорта материалов формата `.rvmat`, используемых в игре DayZ.

Программа должна объединять функции:
- Генератора RVMAT-файлов.
- Визуального 3D-редактора материалов.
- Менеджера текстур.
- Библиотеки пресетов.
- Редактора параметров шейдеров.
- Генератора материалов для состояний повреждения и разрушения объектов.
- Инструмента проверки совместимости материалов с DayZ.

Основная задача — избавить пользователя от необходимости вручную редактировать текстовые RVMAT-файлы и позволить выполнять всю работу через графический интерфейс.

Программа должна не просто генерировать файлы с нужным расширением, а создавать технически корректные материалы, соответствующие структуре и требованиям DayZ.

## 2. Анализ и использование предоставленных примеров

В качестве исходных образцов предоставлены пять файлов:

- `eyemask_damage.rvmat`
- `eyemask_destruct.rvmat`
- `eyemask_decorative.rvmat`
- `eyemask_decorative_damage.rvmat`
- `eyemask_decorative_destruct.rvmat`

Эти файлы необходимо использовать как основные референсы при разработке системы генерации.

В них используется следующая общая структура:

### Основные параметры материала

- ambient
- diffuse
- forcedDiffuse
- emmisive
- specular
- specularPower
- PixelShaderID
- VertexShaderID

В предоставленных образцах используются значения:

- PixelShaderID = Super
- VertexShaderID = Super
- specularPower = 15

Эти значения должны быть доступны для настройки, но при создании нового материала должны автоматически заполняться согласно выбранному пресету.

### Система текстурных стадий

В примерах используются семь текстурных стадий:

**Stage1 — Normal Map**

Пример:
`eyemask_black_nohq.paa`

Отвечает за информацию о нормалях поверхности.

**Stage2 — Detail Texture**

Используется процедурная текстура:

`#(argb,8,8,3)color(0.5,0.5,0.5,1,DT)`

Также присутствует параметр Filter = Trilinear.

**Stage3 — Material Condition Map**

Используется для управления состоянием материала.

В зависимости от типа RVMAT встречаются:

- `generic_damage_mc.paa`
- `generic_destruct_mc.paa`
- Процедурная текстура `#(argb,8,8,3)color(0,0,0,0,MC)`

Программа должна автоматически выбирать соответствующий вариант на основании типа создаваемого материала.

**Stage4 — AS Texture**

Пример:
`eyemask_black_as.paa`

**Stage5 — SMDI Texture**

Пример:
`eyemask_black_smdi.paa`

**Stage6 — Fresnel**

Процедурная текстура:

`#(ai,32,128,1)fresnel(0.88,1.89)`

Параметры Fresnel должны быть доступны для редактирования, если это допускается используемым форматом и шейдером.

**Stage7 — Environment Texture**

Пример:
`dz\data\data\env_land_co.paa`

Все семь стадий должны поддерживать собственные настройки UV-преобразования:

- aside
- up
- dir
- pos
- uvSource

Необходимо сохранить возможность редактирования этих значений через интерфейс.

Важно: приведённая структура является основой для соответствующего типа материала. Нельзя автоматически считать, что все возможные RVMAT DayZ используют исключительно эти семь стадий.

## 3. Архитектура программы

Программа должна иметь модульную архитектуру.

Каждый основной компонент должен отвечать за отдельную задачу.

### 3.1. RVMAT Backend — ядро генерации

Основной модуль, отвечающий за работу с форматом RVMAT.

Функции:
- Создание новых RVMAT-файлов.
- Чтение существующих RVMAT.
- Разбор структуры и параметров.
- Редактирование отдельных параметров.
- Генерация файлов с сохранением корректного синтаксиса.
- Работа с текстурными стадиями.
- Подстановка путей к текстурам.
- Поддержка процедурных текстур.
- Сохранение исходных параметров, которые не редактировались пользователем.
- Проверка структуры перед экспортом.

Особое требование: при открытии существующего RVMAT программа не должна терять неизвестные или неподдерживаемые параметры.

Необходимо реализовать безопасное редактирование с сохранением оригинальной структуры там, где это возможно.

Не следует использовать простую замену текста по шаблону без полноценного разбора структуры.

### 3.2. Material Preview — 3D-предпросмотр

Модуль визуализации материалов.

Должен отображать материал на 3D-объектах в реальном времени.

Предусмотреть модели:
- Сфера.
- Куб.
- Цилиндр.
- Плоскость.
- Тор.
- Параметрическая тестовая модель.
- Возможность импортировать собственную 3D-модель.

Поддержать форматы моделей, необходимые для работы с DayZ, с приоритетом на совместимость с OBJ, FBX и P3D, если соответствующая интеграция доступна.

Возможности:
- Вращение объекта.
- Приближение и отдаление.
- Перемещение камеры.
- Изменение освещения.
- HDRI-окружение.
- Несколько вариантов освещения.
- Отображение UV-развёртки.
- Настройка повторения текстур.
- Отображение сетки.
- Переключение между разными текстурными каналами.
- Сравнение нескольких вариантов материала.

Предпросмотр должен обновляться автоматически при изменении параметров.

**Критически важное требование:** визуализация должна быть ориентирована на DayZ, а не на стандартную универсальную PBR-модель.

Если отдельные возможности игрового шейдера невозможно точно воспроизвести сторонним рендерером, программа должна отображать приблизительный результат и отдельно обозначать отличия от игрового движка.

В перспективе предусмотреть интеграцию с DayZ Tools / Workbench для проверки реального результата.

### 3.3. Texture Manager — менеджер текстур

Отдельный модуль для управления всеми текстурами проекта.

Функции:
- Импорт текстур.
- Загрузка целых папок.
- Предпросмотр изображений.
- Определение разрешения.
- Определение формата.
- Отображение имени и пути.
- Проверка существования файла.
- Проверка совместимости.
- Переименование и замена текстур.
- Автоматическое определение назначения карты по имени файла.
- Ручное назначение текстурных слотов.

Поддержать распространённые исходные форматы: PNG, TGA, JPG, TIFF, BMP.

Также предусмотреть работу с игровыми форматами PAA и PAА-конвертацию через официальные инструменты DayZ Tools, если это технически возможно.

Необходимо учитывать, что исходные изображения и игровые текстуры могут отличаться по формату и обработке.

### 3.4. Preset Manager — система пресетов

Отдельный модуль для создания, хранения и редактирования шаблонов.

Предусмотреть:
- Встроенную библиотеку.
- Создание собственных пресетов.
- Редактирование.
- Копирование.
- Удаление.
- Импорт и экспорт.
- Категории.
- Поиск.
- Избранное.
- Описание каждого пресета.

Категории:
- Металл.
- Пластик.
- Дерево.
- Ткань.
- Кожа.
- Стекло.
- Резина.
- Камень.
- Бетон.
- Другие материалы.

Каждый пресет должен содержать не только визуальные настройки, но и полноценную структуру RVMAT, соответствующую конкретному типу материала и шейдеру.

## 4. Генерация материалов и состояний объекта

Это одна из важнейших функций программы.

Необходимо реализовать отдельную систему создания связанных материалов для разных состояний одного игрового объекта.

Программа должна уметь создавать:

1. Обычный материал.
2. Декоративный материал.
3. Материал повреждённого объекта.
4. Материал разрушенного объекта.
5. Декоративный материал повреждённого объекта.
6. Декоративный материал разрушенного объекта.

Названия файлов должны автоматически формироваться на основе имени основного материала.

Например, если пользователь вводит `myhelmet`, программа должна сформировать комплект:

- `myhelmet.rvmat`
- `myhelmet_damage.rvmat`
- `myhelmet_destruct.rvmat`
- `myhelmet_decorative.rvmat`
- `myhelmet_decorative_damage.rvmat`
- `myhelmet_decorative_destruct.rvmat`

Система должна учитывать, что предоставленные примеры не содержат отдельного обычного `eyemask.rvmat`. Его базовую структуру необходимо определять по дополнительному подтверждённому шаблону, а не придумывать самостоятельно.

### 4.1. Генерация Damage

При выборе состояния Damage программа должна использовать соответствующую карту повреждения.

В предоставленных примерах:
`dz\characters\data\generic_damage_mc.paa`

При этом остальные стадии должны сохранять настройки выбранного базового материала, если они не требуют изменения.

### 4.2. Генерация Destruct

Для состояния Destruct использовать:
`dz\characters\data\generic_destruct_mc.paa`

Программа должна автоматически формировать соответствующий файл и сохранять согласованность с исходным материалом.

### 4.3. Генерация Decorative

В предоставленном примере `eyemask_decorative.rvmat` используется процедурная текстура Stage3:

`#(argb,8,8,3)color(0,0,0,0,MC)`

Для декоративного варианта повреждений и разрушения используются соответствующие карты Damage и Destruct.

### 4.4. Групповая генерация

Предусмотреть возможность создания всех связанных RVMAT за одно действие.

Пользователь должен иметь возможность:
- Выбрать, какие состояния создавать.
- Настроить общий материал.
- Настроить отдельные параметры каждого состояния.
- Назначить отдельные текстуры для каждого варианта.
- Просмотреть итоговый список файлов.
- Сгенерировать весь комплект.
- Экспортировать комплект в одну папку.

Изменение общей настройки должно распространяться на все связанные материалы, если пользователь не переопределил её индивидуально.

Необходимо предусмотреть отображение различий между вариантами.

## 5. Интерфейс настройки материала

Создать полноценную панель редактирования параметров.

Для всех числовых параметров предусмотреть:
- Ползунок.
- Поле точного ввода.
- Минимальное и максимальное значение.
- Кнопку сброса.
- Отображение текущего значения.

Параметры сгруппировать по разделам.

### Общие параметры

- Ambient.
- Diffuse.
- Forced Diffuse.
- Emmisive.
- Specular.
- Specular Power.
- Pixel Shader ID.
- Vertex Shader ID.

Для цветовых параметров предусмотреть:
- Ввод RGBA.
- Выбор цвета через цветовую палитру.
- Редактирование каждого канала.
- Сброс к исходному значению.

### Настройки текстурных стадий

Для Stage1–Stage7 создать отдельные вкладки или раскрывающиеся панели.

Каждая панель должна содержать:
- Назначенную текстуру.
- Миниатюру.
- Путь к файлу.
- UV Source.
- Aside.
- Up.
- Dir.
- Pos.
- Дополнительные параметры, если они присутствуют в соответствующей стадии.

Для Stage6 отдельно предусмотреть настройки процедурной Fresnel-текстуры.

Для Stage2 предусмотреть редактирование Filter и параметров процедурной текстуры.

Пользователь должен иметь возможность включать и отключать отображение отдельных текстурных стадий в диагностическом предпросмотре.

Отключение стадии в предпросмотре не должно автоматически удалять её из итогового RVMAT.

## 6. Расширенные инструменты текстур

Добавить дополнительные возможности:

- Отображение RGB-каналов отдельно.
- Отображение Alpha Channel.
- Просмотр Normal Map.
- Проверка направления нормалей.
- Просмотр SMDI.
- Проверка разрешения текстур.
- Сравнение текстур.
- Проверка цветового пространства.
- Настройка UV Tiling.
- Настройка UV Offset.
- Настройка UV Rotation, если поддерживается используемым форматом.
- Автоматическое сопоставление текстур по общему имени.

Автоматическое определение должно учитывать типовые суффиксы файлов:
- `_co`
- `_nohq`
- `_as`
- `_smdi`

Также предусмотреть ручную настройку, поскольку пользовательские проекты могут использовать другие названия.

## 7. Система проверки RVMAT

Реализовать отдельный инструмент диагностики.

Он должен проверять:

1. Корректность синтаксиса.
2. Наличие обязательных параметров для выбранного типа материала.
3. Корректность Stage1–Stage7.
4. Корректность UV Transform.
5. Существование текстур.
6. Правильность путей.
7. Допустимость процедурных текстур.
8. Соответствие текстурных форматов.
9. Корректность ссылок на игровые ресурсы.
10. Наличие всех необходимых файлов в комплекте.

Ошибки разделить на категории:

- Критические ошибки.
- Предупреждения.
- Информационные сообщения.

При выборе ошибки программа должна автоматически переходить к соответствующему параметру.

Также предусмотреть режим проверки по правилам DayZ Tools, если он доступен.

## 8. Работа с путями и структурой проекта DayZ

Это обязательный функционал.

Необходимо предусмотреть поддержку структуры проектов DayZ и P: Drive.

Пользователь должен иметь возможность указать корневую папку проекта.

Программа должна:
- Распознавать структуру папок.
- Формировать корректные игровые пути.
- Проверять наличие файлов.
- Предупреждать о неправильных путях.
- Поддерживать относительные пути.
- Различать игровые пути и локальные пути Windows.
- Проверять регистр и расширения файлов.
- Предупреждать о ссылках на отсутствующие ресурсы.

Необходимо учитывать, что путь к текстуре внутри RVMAT не всегда совпадает с физическим путём на компьютере.

При экспорте программа должна использовать корректные пути, предусмотренные структурой проекта DayZ.

- Destruct.

Предусмотреть:
- Автоматическое создание папок.
- Выбор директории.
- Пакетный экспорт.
- Проверку перед экспортом.
- Предупреждение о перезаписи файлов.
- Сохранение относительных путей.
- Возможность повторного открытия проекта.

## 12. Техническая реализация

Рекомендуется использовать модульную архитектуру с разделением логики, интерфейса, генерации файлов и визуализации.

Предпочтительные технологии:

- Python или C++ для основной логики.
- PySide6 / Qt для графического интерфейса.
- Подходящий 3D-движок или библиотеку с поддержкой PBR-визуализации.
- Отдельный модуль парсинга и генерации RVMAT.
- SQLite или JSON для хранения пресетов и настроек.

Конкретный выбор технологий должен учитывать производительность, стабильность и возможность интеграции с DayZ Tools.

Программа должна работать локально, без обязательного подключения к интернету.

## 13. Интеграция с DayZ Tools

Предусмотреть отдельный раздел настроек интеграции.

Возможности:
- Указание расположения DayZ Tools.
- Указание расположения Workbench.
- Указание P: Drive.

- Использование доступных официальных инструментов конвертации текстур.
- Проверка экспортированных материалов в целевой среде.

Необходимо исследовать возможности интеграции с реальным рендерером DayZ.

Не следует утверждать, что обычный сторонний PBR-рендерер полностью воспроизводит шейдеры Enfusion.

Если прямой вызов игрового рендерера невозможен, предусмотреть два режима:

1. Предварительная визуализация в собственном 3D-окне.
2. Проверка итогового материала средствами DayZ Tools / Workbench.

## 17. Главный принцип разработки

Программа должна быть специализированным инструментом именно для DayZ.

Необходимо строго разделять:

- **RVMAT Backend** — реальный формат файлов, синтаксис, шейдеры и генерация.
- **Material Preview** — визуализация и предварительный просмотр.
- **Texture Manager** — управление текстурами.
- **Preset Manager** — управление шаблонами.
- **Damage System** — генерация связанных материалов для состояний повреждения и разрушения.
- **DayZ Tools Integration** — проверка и взаимодействие с инструментами игры.

Нельзя заменять реальную структуру RVMAT универсальными PBR-параметрами.

Все функции, которые непосредственно влияют на итоговый файл, должны быть основаны на проверенных правилах формата DayZ.

**Итоговый результат:** полноценная самостоятельная программа DayZ RVMAT Studio, позволяющая создавать, настраивать, визуализировать и экспортировать игровые материалы, включая полные комплекты состояний объекта, без необходимости вручную писать код RVMAT.
