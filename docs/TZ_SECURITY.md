# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
# DayZ RVMAT Studio — повышение безопасности, надёжности и качества сборки

## 1. Цель

Устранить риски, выявленные при аудите репозитория: обработка недоверенных файлов (FBX, PAA, OBJ, `.rvproj`, `.rvpreset`, RVMAT), запись и чтение по путям из данных, запуск внешних программ, цепочка поставок зависимостей и CI. Функциональность приложения не меняется.

## 2. Область и модель угроз

Приложение — локальное настольное (tkinter), без сети. Источник угроз — файлы, полученные от третьих лиц (чужие моды, проекты, пресеты, модели), а также подмена пользовательских настроек. Целевые свойства:

- открытие любого файла не приводит к зависанию, исчерпанию памяти или аварийному завершению — только к понятной ошибке;
- открытие чужого проекта не читает и не записывает файлы вне разрешённых папок;
- приложение не запускает программы, не выбранные пользователем явно;
- сборка и зависимости воспроизводимы и проверяемы.

## 3. Задачи

Приоритеты: **P1** — обязательно, **P2** — желательно в этом цикле, **P3** — по возможности.

### 3.1. Защита парсеров от некорректных и вредоносных файлов — P1

Файлы: `core/fbx.py`, `core/paa.py`, `core/meshes.py`, `core/textures.py`, `backend/parser.py`.

| № | Требование |
|---|-----------|
| 1.1 | Распаковка zlib в бинарном FBX — с ограничением размера (`decompressobj().decompress(raw, max_length=N)`); лимит задаётся константой модуля. |
| 1.2 | Количество элементов массива `n` и длины `clen`/`end` проверяются на выход за границы данных и на разумный максимум. |
| 1.3 | Лимит глубины вложенности узлов FBX (рекурсия `node()` заменяется итеративной или ограничивается глубиной). |
| 1.4 | PAA: лимиты на `w`, `h`, `w*h` и `out_len` LZO до начала декодирования; ошибки декомпрессора — только `PaaError`. |
| 1.5 | Лимит размера входного файла для FBX, OBJ, PAA, RVMAT, JSON (проект/пресеты/настройки); значения — в одном месте (`core/limits.py`). |
| 1.6 | `Image.MAX_IMAGE_PIXELS` задан явно; ошибка `DecompressionBombError` обрабатывается. |
| 1.7 | Любые `struct.error`, `IndexError`, `zlib.error`, `ValueError`, `MemoryError` при загрузке преобразуются в `FbxError`/`PaaError`/`MeshError` и показываются пользователю без падения приложения. |
| 1.8 | Проверка регулярных выражений ASCII FBX и RVMAT на катастрофический откат; при необходимости — переписать токенизатор без бэктрекинга. |

**Приёмка:** набор испорченных образцов (zip-бомба, обрезанные файлы, огромные `n`, цикл в узлах, глубокая вложенность, мусор вместо заголовка) открывается за < 2 с, потребляет < 512 МБ и завершается контролируемой ошибкой. Добавлены тесты в `tests/test_malformed.py`.

### 3.2. Безопасная работа с путями — P1

Файлы: `core/export.py`, `core/texnames.py`, `core/project.py`, `core/presets.py`, `core/autoload.py`.

| № | Требование |
|---|-----------|
| 2.1 | Функция `ensure_within(path, root)` (через `resolve()`): итоговый путь записи каждой операции экспорта должен лежать внутри `out_dir`; иначе `ExportError`. |
| 2.2 | `find_texture`: источники из RVMAT/`tex_map` принимаются только внутри `project_root`, папки проекта и явно добавленных пользователем директорий; абсолютные пути и `..` вне этих корней отклоняются с предупреждением. |
| 2.3 | `Project.title` проходит через `safe_name` при формировании имени автосохранения и любого другого имени файла. |
| 2.4 | `Preset.id` из файлов `*.rvpreset` и импорта ограничивается шаблоном `^[0-9a-f]{12}$`; имя файла пресета строится только из валидного id. |
| 2.5 | При открытии `.rvproj` значения `project_root`, `export_dir`, `tex_map`, `textures`, `model_path` показываются пользователю в диалоге подтверждения, если указывают за пределы папки самого проекта. |
| 2.6 | `open_folder`: проверка `Path.is_dir()`, передача пути после `--` для `xdg-open`/`open`. |

**Приёмка:** тесты с проектом/пресетом, содержащим `..\..`, абсолютные пути, UNC-пути и имена с разделителями; ни один файл не создан и не прочитан вне разрешённых корней.

### 3.3. Запуск внешних программ — P1

Файлы: `core/dayztools.py`, `core/texnames.py`, `core/settings.py`.

| № | Требование |
|---|-----------|
| 3.1 | Пути к `ImageToPAA.exe` и `workbenchApp.exe` хранятся только в пользовательских настройках и не читаются из `.rvproj`/пресетов. |
| 3.2 | Перед запуском проверяется, что файл существует, является файлом и его имя совпадает с ожидаемым (регистр не важен); иначе явная ошибка. |
| 3.3 | При первом запуске внешнего exe из нового пути — подтверждение пользователя (путь запоминается в настройках). |
| 3.4 | Все вызовы `subprocess` — списком аргументов, без `shell=True`, с `timeout`; тест на отсутствие `shell=True` (grep-тест). |

## 5. Критерии приёмки

1. Все тесты проходят на Linux и Windows; новые тесты на испорченные файлы и выход за пределы папок включены в CI.
2. Ни один из образцов из `tests/malformed/` не вызывает падения, зависания > 2 с или расхода памяти > 512 МБ.
3. Экспорт и автозагрузка не создают и не читают файлы вне разрешённых корней (проверено тестами).
4. В CI у всех workflow явно заданы `permissions`, действия закреплены по SHA, включены Dependabot и CodeQL.
5. В репозитории есть `LICENSE`, `SECURITY.md`, раздел «Безопасность» в README.
6. Обратная совместимость: существующие `.rvproj`, `.rvpreset` и настройки открываются без потери данных.

## 6. Не входит в задачу

Изменение формата RVMAT, нового функционала редактора, смена GUI-библиотеки, сетевые функции.
